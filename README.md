# Zephyr Workbench

## 目标

这个工作台为 Zephyr 源码维护提供轻量的导航、任务上下文和长期知识。源码、构建结果和运行行为始终是最终事实。

工作台只回答四类问题：

- `map.md`：问题应该先去源码仓的哪里定位。
- `topics/`：某个稳定主题目前已经确认了什么。
- `tasks/`：当前要解决什么、边界是什么、怎样算完成。
- `decisions.md`：为什么选择了某个跨任务或跨模块方案。

同一信息只保留一个正式位置，不再为人和 AI 维护两份内容。

## 目录

```text
zephyr-workbench/
├── README.md
├── map.md
├── decisions.md
├── topics/                 # 出现第一个真实专题时再创建
│   └── <topic>.md
└── tasks/
    └── <id>-<title>.md
```

Zephyr 仓库根目录的 `AGENTS.md` 是 AI 协作的唯一规则入口。

## 使用路径

### 有明确任务

1. 先读对应任务文件。
2. 需要定位源码时查 `map.md`。
3. 有相关专题时再读对应 `topics/<topic>.md`。
4. 进入源码和测试验证，不以工作台文档代替事实。

### 没有任务文件

直接从用户目标和源码开始。只有工作预计跨会话、需要交接或涉及多个模块时才新建任务文件。

### 任务结束

- 更新任务状态和验证结果。
- 只有产生可复用知识时才更新或创建专题。
- 只有形成影响多个任务、模块或后续维护方式的选择时才记录决策。

## 最小任务格式

```markdown
---
id: ZEPHYR-TASK-XXXX
status: backlog | in-progress | blocked | done
---

# 标题

## 目标与范围

## 完成标准

## 当前结论

## 下一步
```

按需增加风险、相关路径或排查记录，不要求为每个任务填满固定字段。任务状态只写在 front matter，不再通过移动目录表达。

## 最小专题格式

```markdown
---
title: <主题>
scope: <源码范围>
last_verified: YYYY-MM-DD
source_revision: <commit>
---

# 主题

## 入口与关键路径

## 核心机制

## 常见修改与验证

## 待确认问题
```

专题按源码主题组织，不按读者类型、任务阶段或文档类型复制。

## 维护约束

- 不预建空目录；内容出现时再建。
- 不维护没有实际消费者的 YAML 注册表、Dashboard 或指标目录。
- `map.md` 只做路由，不继续扩张为 Zephyr 百科。
- 任务过程中的临时假设留在任务文件，确认后的稳定知识进入专题。
- 历史结论与当前源码冲突时，以当前源码和验证结果为准。
